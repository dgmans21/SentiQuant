# SentiQuant

한국 주식 뉴스의 논조(긍정/부정/중립)를 분류하고, 그 논조가 실제 주가와 관련이 있는지 **정직하게** 검증한 개인 프로젝트입니다.

> "뉴스로 내일 주가를 맞힐 수 있는가"라는 첫 가설은 기각됐습니다. 대신 "이 기사의 논조가 무엇인가"로 과제를 다시 정의했고, 그 결과를 과대포장하지 않기 위해 스스로 발견한 평가 버그를 고치고, 통계적으로 유의하지만 작은 효과크기를 있는 그대로 보고했습니다.

전체 스토리(그래프·스크린샷 포함)는 [`portfolio/sentiquant.html`](portfolio/sentiquant.html)에, 날짜별 상세 작업 기록은 [WORKLOG.md](WORKLOG.md)에 있습니다.

## 핵심 결과

| 항목 | 값 |
|---|---|
| 논조 분류 정확도 (test) | **85.1%** (F1 macro 83.6%) — 프로덕션 v6, test 7,735건. 주가 직접 예측 방식(최고 38.5%) 대비 2배 이상 |
| 수집 종목 | 20개 (10개 섹터 분산) |
| 수집 뉴스 | 121,891건 (NAVER 뉴스검색 API, 2026-09-19 23시경 수집분까지로 고정) |
| Qwen3-4B 논조 라벨링 | 121,891건 전량 — 중립 59,306 / 긍정 27,625 / 무관 22,205 / 부정 12,738 / 파싱실패 17 |
| v6 학습 표본 | 51,566건 (v6 학습 시점에 라벨링이 끝난 분량. 이후 라벨링이 늘었지만 아래 검증 결과 때문에 v6을 유지) |
| RAG 검색 인덱스 | 99,669건 (무관·파싱실패 제외). 이 중 이후 수익률 정보가 붙어 있는 기사는 24,695건 |
| 논조-주가 상관관계 | 통계적으로 유의(p<0.0001)하나 **효과크기는 작음**(r²<2%) — 매매 신호로 쓸 근거는 아님 |

## 이 프로젝트가 보여주는 것

- **실패한 가설을 인정하고 방향을 바꾼 판단력**: 뉴스 헤드라인으로 익일 주가 방향을 맞히려던 첫 시도는 찍기 확률 수준에서 벗어나지 못했습니다. 원인을 분석해 "라벨을 주가가 아니라 텍스트 자체의 논조로 재정의"하는 방향으로 전환했고, 정확도가 2배 이상 뛰었습니다.
- **자기 검증 능력**: 종목별 성능을 점검하다가 기존 평가 방법론(train/val/test 분할)이 특정 종목들을 검증셋에서 통째로 누락시키는 버그를 스스로 발견하고 수정했습니다. "81.3%"라는 초기 결과가 사실은 일부 종목에만 편중된 수치였다는 것을 밝히고 바로잡았습니다.
- **정직한 통계 보고**: 논조와 실제 수익률의 상관관계를 여러 시차(t+1~t+10)로 나눠 검증하며, 처음엔 과장되게 해석했던 결과("역인과관계가 확인됐다")를 효과크기 기준(Cohen's r)으로 다시 검토해 "약한 신호" 수준으로 스스로 정정했습니다.
- **실전 도구화(RAG)**: 분류기 하나로 끝내지 않고, 임베딩 기반 유사사례 검색 + Qwen3-4B 설명 생성을 결합한 RAG 파이프라인을 FastAPI + Next.js로 구현했습니다. LLM 프롬프트에도 "확정적 예측처럼 말하지 말 것"을 명시해, 도구 자체가 결과를 과장하지 않도록 설계했습니다.
- **결론을 계속 재검증하는 태도**: 학습 데이터를 24%(+5,816건) 늘렸을 땐 정확도가 0.3%p밖에 안 움직여 "이 구조는 데이터를 늘려도 정체된다"고 결론 내렸습니다. 하지만 이후 라벨링을 전량 완료하며 데이터가 69% 늘어나자 정확도가 83.8% → 85.1%로 다시 올랐습니다. "정체"가 아니라 "증가폭이 부족했을 뿐"이었다는 걸 확인하고 기존 결론을 정정했습니다.
- **스스로 낸 개선을 스스로 철회**: 라벨 품질을 개선해 재학습한 모델(v8·v9)이 정확도 86.1%·88.9%로 "크게 개선"돼 보였지만, 채점 정답지도 함께 바뀐 착시라는 것을 같은 행·같은 정답지로 교차평가해서 확인하고 철회했습니다. 이어서 사람 블라인드 검증으로 "라벨 자체는 나아졌는가"를 따로 확인했습니다. 자세한 내용은 아래 "라벨 품질 검증" 참고.

## 라벨 품질 검증과 모델 교체 보류 (2026-09)

**가설**: 제목+요약(약 200자)만 보고 매긴 라벨은 "중립 ↔ 긍정/부정" 경계를 놓칠 것이다. 그래서 기사 본문을 스크래핑해 Qwen3-4B로 다시 라벨링했습니다(Qwen은 파인튜닝하지 않고 입력만 바꿈. 가중치가 학습되는 건 KLUE-BERT뿐).

| 단계 | 결과 |
|---|---|
| 본문 재라벨링 | 분류기와 라벨이 어긋나는 애매한 기사 7,674건(네이버 2,524 + 그 외 언론사 5,150) 중 4,471건(58%)의 라벨이 바뀜. 후보를 모델 불일치로 골랐기 때문에 이 비율은 전체 라벨 오류율이 아님 |
| 재학습 v8·v9 | test 정확도 86.12%·88.91% (v7 84.73%) — 처음에는 개선으로 봤음 |
| **교차평가 → 철회** | v9 test 12,172행을 v7/v8/v9로 각각 추론해 **같은 정답지**로 채점. 새 라벨 기준 v7 89.74% / v8 90.21% / v9 88.91%, 이전 라벨 기준 84.91% / 85.11% / 84.51%. 새 라벨로 학습한 적 없는 v7도 새 정답지로 채점하면 89.7%였고, 라벨이 안 바뀐 행에서는 v9가 v7·v8보다 오히려 낮았음. 즉 "+4.18pp"는 정답지가 바뀐 효과 |
| 착시의 원인 | ① 교정 후보를 모델 불일치로 골라 교정이 val/test에 몰림(train 2.5% vs test 6.7%) ② 정답지를 모델 예측 쪽으로 고치면 모델 점수가 오름 ③ 분류기는 제목+요약만 보므로 본문 기준 라벨을 흉내 낼 수 없고, 교정은 3.9%뿐이라 라벨 기준이 섞임 |
| 사람 블라인드 검증 (1번 시트) | 라벨이 바뀐 기사 50건. 자유 표현으로 답하게 했더니 "약한 긍정"을 긍정으로 읽느냐 중립으로 읽느냐에 따라 새 라벨 지지율이 72% ↔ 41%로 뒤집혀 **결론을 내지 못함** |
| 사람 블라인드 검증 (2번 시트) | 다른 50건. 답을 긍/부/중/무 한 글자로 고정하고 "방향을 직접 말하는 표현이 있으면 그 방향, 없으면 중립"이라는 규칙을 명시. 사람 판단이 새(본문) 라벨과 일치 33건 / 이전(요약) 라벨과 일치 11건 / 둘 다 아님 6건 → 둘 중 하나와 일치한 44건 중 **새 라벨 75%**(95% CI 61~85%, p≈0.001). 중립→긍정 27건 중 21 vs 5, 중립→부정 10건은 4 vs 5(지지 없음) |

**결론과 결정**
- 요약문 라벨과 본문 라벨이 갈리는 기사에서는 사람도 본문 기반 라벨 쪽에 더 자주 동의했습니다. 그러나 이 라벨로 학습해도, 제목+요약만 입력으로 받는 분류기의 정확도는 같은 잣대에서 오르지 않았습니다.
- 그래서 **프로덕션은 v6을 유지**하고 모델 개선은 여기서 종료했습니다. 데이터 수집도 2026-09-19 23시경 수집분(라벨 121,891건)으로 고정했습니다.
- "라벨이 더 나아졌다"와 "그 라벨로 분류기가 나아진다"는 별개라는 것이 이 검증의 결론입니다.

**한계 (정직하게)**
- 사람 검증은 평가자 1명, 100건 중 결론이 나는 것은 2번 시트 50건뿐이고, 답이 긍정 쪽으로 치우쳐 있습니다(2번 시트 46%). 판단 규칙도 Qwen 프롬프트에서 따온 것이라 완전히 독립된 정답이 아니고, 라벨이 바뀐 기사만 본 것이라 전체 라벨 정확도는 아닙니다.
- 학습 run 간 변동(시드)은 측정하지 않았습니다. 1pp 안팎의 정확도 차이는 해석하지 않았고, 교차평가의 z값은 test 행 샘플링 오차만 반영합니다.
- v6은 split이 달라 v7~v9와 공정 비교가 되지 않아 교차평가에서 제외했습니다.
- v6의 85.1%와 RAG 검색 정밀도(P@5 98.5%, 80개 쿼리)는 각각 당시 학습·인덱스 기준으로 잰 값입니다. 최신 인덱스(99,669건)와 재라벨링 결과로 다시 측정하지 않았습니다.

## 시스템 구성

```
NAVER 뉴스 API ─┐
                ├─▶ 뉴스-주가 매칭 ─▶ Qwen3-4B 논조 라벨링 ─▶ KLUE-BERT 파인튜닝(분류기)
yfinance(주가) ─┘                                                    │
                                                                      ▼
                                        임베딩 검색(과거 유사사례 + 실제 수익률)
                                                                      │
                                                                      ▼
                                    FastAPI(/analyze, /explain) ─▶ Next.js 웹 UI
```

**기타** NAVER API HUB · yfinance · RTX 4060 Ti(로컬 4bit 추론)

## 로컬 실행

```bash
# 1. 환경
conda activate unsloth_env   # Python 3.12, PyTorch 2.11 + CUDA 13.0
pip install -r requirements.txt   # (또는 DATA_PIPELINE_RULES.md 참고해 개별 설치)

# 2. .env에 NAVER API 키 필요 (NAVER_API_KEY_ID, NAVER_API_KEY)

# 3. RAG 데모 실행 (사전 학습된 데이터/모델 필요 — DATA_PIPELINE_RULES.md 참고)
cd api && uvicorn main:app --reload        # :8000
cd web && npm install && npm run dev        # :3000
```

`data/`, `models/`는 용량 문제로 git에 포함하지 않았습니다. 재현하려면 DATA_PIPELINE_RULES.md의 순서대로 파이프라인을 처음부터 돌려야 합니다.
